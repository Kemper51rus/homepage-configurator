# Стабильность прокрутки dashboard

## Причина подёргивания

Выравнивание высот карточек раньше сбрасывало `style.height` на живых DOM-элементах, измеряло их через `getBoundingClientRect()` и возвращало итоговые высоты. Промежуточный layout запускал browser scroll anchoring. Глобальный MutationObserver реагировал в том числе на перерисовку FPS-индикатора каждую секунду. В середине dashboard это давало постоянное смещение скролла, хотя итоговая высота документа не менялась.

## Исправление

- Натуральные высоты измеряются на временных невидимых inert-копиях вне потока, с той же шириной и в том же CSS-контексте.
- Живые карточки получают только изменившиеся конечные высоты, без промежуточного сброса. Поддерживаются рост и уменьшение контента.
- MutationObserver игнорирует FPS/topbar и собственные измерительные копии; отслеживает изменения service groups и их контента.
- FPS markup заменяется только при реальном изменении отображаемого состояния.

Глобальное отключение scroll anchoring и принудительное восстановление `scrollTop` не используются.

## Проверка

```bash
npm run check
HOMEPAGE_BROWSER_SMOKE_URL=http://<runtime>:3000/ node scripts/dashboard-scroll-smoke.mjs
```

Browser smoke проверяет середину страницы и нижнюю границу на ширинах 1440, 1920 и 1100px. Дополнительные невидимые DOM-мутации в карточке моделируют обновление виджета без изменения layout. На старом runtime тест воспроизводил смещение 153px за 3 секунды. Unit-тесты `service-row-height-balancer.test.mjs` проверяют отсутствие временного сброса высот, идемпотентность, рост/уменьшение и cleanup; `particles-fps.test.mjs` проверяет FPS render.
