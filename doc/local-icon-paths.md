# Локальные иконки и повторные ingress-префиксы

Локально сохранённая иконка Configurator имеет канонический путь `/api/config/icon/<filename>`.

В повреждённых записях встречался путь вида:

```
/api/ingress/homepage_ingress/api/ingress/homepage_ingress/api/config/icon/help.ico
```

До server-side compatibility route такой адрес возвращал 404, хотя сам `/api/config/icon/help.ico` существовал. Источник внесения ingress-префиксов не установлен: штатное повторное сохранение на обследованном runtime их не добавляло.

Configurator нормализует только однозначные root-relative пути локальных иконок с одним или несколькими ingress-префиксами. Общий renderer исправляет такие старые записи для отображения. При сохранении сервисов/закладок через формы, YAML-редактор и перенос между типами канонический путь записывается в конфигурацию.

Начиная с `0.8.0-beta.16`, server-side route `/api/ingress/[...path]` дополнительно принимает только старые локальные icon URL и перенаправляет их на канонический icon API с `307` и `Cache-Control: no-store`. Это нужно для старой разметки/уже открытых вкладок, где новый renderer ещё не запущен. Route не выполняет proxy/fetch, не поддерживает произвольный ingress и не отменяет Authentik; посторонние пути и query отклоняются.

Внешние URL, `href` карточек и другие строки не переписываются. Нестандартные пути с query/fragment, traversal или encoded-разделителями не трактуются как канонические локальные файлы.

Это восстановление пути локального icon API, а не поддержка размещения всего Homepage под произвольным ingress base path. Изменения относятся только к Configurator; Studio не меняется.

Проверки: `npm run check` — unit-тесты нормализации и API сохранения, корректность обеих core patch variants и fresh install/uninstall smoke.
